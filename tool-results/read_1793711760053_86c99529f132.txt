   465→  the sidebar to a 70px icon rail, stacks the toolbar, and keeps the tables
   466→  at their 930/900px minimums inside horizontal ScrollViews, per the
   467→  integration notes. The detail and confirmation dialogs fit a 390px
   468→  viewport with 20px margins.
   469→- **Web-preview glue (hand-off untouched)** — two rules in the preview
   470→  wrapper only: (1) on desktop the tables' `width: "100%"` resolves
   471→  against the horizontal ScrollView's shrink-wrapped content container, so
   472→  the content container is stretched to the card's real width (the
   473→  hand-off's `compact` breakpoint is respected below 900px); (2)
   474→  react-native-web gives every relatively-positioned view a default
   475→  z-index 0, which trapped the row dropdown (z-index 30) inside its own
   476→  row's stacking context so later rows painted over it — while a row menu
   477→  is open, the ancestors between the table card and the dropdown are
   478→  neutralised so the dropdown renders above the rows below it.

   480→## Known notes
   481→
   482→- The hand-off references the icon name `file-archive`, which does not exist
   483→  in the MaterialCommunityIcons glyphmap (7,448 names checked — the closest
   484→  real glyph is `zip-box`). Without a fix the two ZIP rows render a "?"
   485→  fallback glyph. `glyphPatches.ts` (imported first in `App.tsx`) aliases
   486→  `file-archive` → `zip-box` at runtime so the intended archive icon renders,
   487→  **without touching the byte-identical screen code**. If you'd rather change
   488→  the design source, replace `'file-archive'` with `'zip-box'` in the screen
   489→  and delete the patch file.
   490→- The admin-dashboard hand-off (screen 14) names the Feather icon
   491→  `shield-check`, which also does not exist in the Feather glyphmap (only
   492→  `shield` / `shield-off`). `glyphPatches.ts` aliases it to `shield` the
   493→  same way, again without touching the byte-identical screen code.
   494→- Same situation on the scan-result screen: the hand-off uses `shield-minus`,
   495→  which also does not exist in the glyphmap. `glyphPatches.ts` aliases it to
   496→  the real minus-shield glyph `shield-remove` (Material Design Icons names
   497→  "minus" "remove"), again without touching the byte-identical screen code.
   498→- On Android/iOS `Alert.alert` is the real native dialog. react-native-web's
   499→  `Alert` is a silent no-op, which the web preview bridges to a browser
   500→  confirm dialog — not part of this Expo package.
