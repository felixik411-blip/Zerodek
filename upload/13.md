# Security Scanner — Admin Sign In Screen

## Implementation brief

Build the **Admin Sign In** screen shown in the supplied reference image using **React Native + TypeScript + Expo**.

Implement the UI and basic form interactions only. Reuse the project's existing design tokens, navigation, shared components, and icon library where possible. Do not invent backend authentication behavior or claim that sign-in succeeds without a real authentication service.

## Screen structure

Create a full-height, two-column desktop layout:

- **Left panel:** approximately 46% of the viewport width, pale blue-white background.
- **Right panel:** approximately 54% of the viewport width, white background.
- On narrower screens, stack the panels vertically and keep the sign-in form accessible without horizontal scrolling.
- Use a full-height layout with generous whitespace and a subtle dividing edge between panels.

## Right panel — Sign-in card

### Card header

### Form fields

**Password**
- Label: `Password`

- Thin light-blue border.
- Rounded corners (about 7 px).

### Forgot password

Place a right-aligned blue text action below the password input:

`Forgot your password?`

It should navigate to the existing password-recovery screen if one exists. Otherwise, expose it as a callback/placeholder integration point; do not invent a route.

### Sign-in button

Full-width bright-blue button:
- Text: `Sign in`
- Right-arrow icon.
- White text, rounded corners, approximately 49 px high.
- Show a loading/disabled state while a supplied sign-in callback is running.
- Validate that both fields are non-empty before calling the callback.
- Display concise inline validation feedback for missing values.
- Do not display a successful login state unless the real authentication handler reports success.

### Security notice

At the bottom of the card, show a pale-blue information strip with an info icon and this text:

`This area is for authorised staff only. Please do not share your login details.`

Use muted blue text and a soft pale-blue background.

## Interaction requirements

- Username/email field accepts text.
- Password field accepts text and toggles between hidden and visible.
- Sign in validates required fields and invokes an injected authentication callback only when valid.
- Forgot-password action uses the project's existing navigation or an injected callback.
- Use accessible labels and suitable keyboard/autofill settings where supported.
- Dismiss the keyboard appropriately on mobile.
- Never hard-code credentials or store passwords locally.
