# Help & About Screen — Security Scanner

## Implementation brief

Create the **Help & About** screen for the Security Scanner app using **React Native + TypeScript + Expo**. Match the supplied reference screenshot closely.

### Scope

- Implement this screen only.
- Reuse the project's existing shared sidebar, top header, typography, colors, spacing, and navigation conventions where available.
- This is a desktop-oriented layout based on the screenshot. Preserve the two-column shell: dark left sidebar and light main content area.
- Keep the topic cards and search field interactive. Do not invent backend support or claim that searches are connected to a knowledge base.

## Screen layout

### 1. App shell

**Sidebar**
- Dark navy background, approximately 280 px wide in the 1536 × 1024 reference.
- Brand row at the top: blue shield icon and `Security Scanner` wordmark; “Scanner” uses a light-blue accent.
- Navigation items, in order:
  1. Home
  2. History
  3. Quarantine, with a red circular badge showing `2`
  4. Settings
  5. Help & About — active item
- Active item has a blue/navy highlight, rounded corners, and white icon/text.
- At the bottom, a divider and privacy note with shield icon:
  - **Files stay on your phone by default.**
  - `We don't upload your files without your permission.`

**Top header**
- White header across the main content area, about 60 px tall, with a subtle bottom border.
- Right aligned user icon, `User`, and downward chevron.

**Main content**
- Very light blue-white background.
- Consistent horizontal padding of about 36–42 px.
- Use a responsive scroll container so content remains reachable at smaller heights.

### 2. Page heading

At the top of the content:
- Blue question-circle icon in a pale-blue rounded square.
- Title: **Help & About**
- Subtitle: `Find answers to common questions and learn more about Security Scanner.`

### 3. Search field

A white bordered card containing a full-width search input:
- Search icon on the left.
- Placeholder: `Search help topics...`
- Pale blue border, rounded corners, approximately 42 px tall.
- Filter the suggested topic list as the user types. Match text case-insensitively against each topic's title, description, and answer.
- If no topic matches, show a compact empty state: `No help topics found.`

### 4. Suggested topics

Section label: **Suggested topics**

Show five large white cards, each with a thin pale-blue border and rounded corners. Each card contains a colored icon tile, title, short description, and right chevron.

Topics and copy:

1. **How file scanning works**
   - Description: `We check files for known signs of malware using trusted threat information.`
   - Icon: shield/check, blue tile.
   - Suggested answer: Explain that scans look for known indicators and that no scanner can guarantee a file is safe.

2. **What scan results mean**
   - Description: `Learn what the different results (threat found, needs review, no known threat, or could not decide) mean and what to do next.`
   - Icon: document, green tile.
   - Suggested answer: Briefly define each result:
     - Threat found: malicious indicators were detected; do not open the file or link.
     - Needs your review: suspicious indicators were detected; treat it cautiously.
     - No known threat: no known indicators were found, but this is not a guarantee of safety.
     - Could not decide: the scan could not reach a reliable conclusion.

3. **What quarantine does**
   - Description: `Quarantine isolates risky files so they can’t harm your device. You can restore or delete them later.`
   - Icon: archive box, orange tile.
   - Suggested answer: Explain that quarantined files are isolated. Recommend keeping a risky file quarantined unless the user has verified it is safe. Deletion is permanent.

4. **How link checking works**
   - Description: `We check links for known dangerous patterns and domains. This helps you avoid risky websites and phishing attempts.`
   - Icon: link, purple tile.
   - Suggested answer: Explain that a link check compares available indicators with known dangerous patterns and domains; it cannot guarantee website safety.

5. **Your privacy**
   - Description: `We keep your files on your device by default and don’t upload them without your permission.`
   - Icon: lock, teal tile.
   - Suggested answer: State the privacy behavior shown in the app: files remain on the device by default and are not uploaded without permission.

Selecting a topic should open an in-screen detail panel or modal showing its title and answer, with a clear close/back control. Use the project's existing modal/navigation pattern if one exists.

- **Borders:** pale blue `#D8E7FA`.

- Use modest corner radii (8–12 px), subtle borders, and restrained shadows if consistent with the rest of the app.
- Icons should come from the project's existing icon package if available. If not, use an already installed compatible icon library; do not add a new dependency without checking the project first.

## Interaction requirements

- Search input filters the five topic cards live.
- Tapping a topic opens its answer/detail view.
- Provide a visible empty state when search finds no matches.
- Sidebar navigation items should use the app's existing navigation callbacks/routes. Do not create fake route names; if route names are not yet available, accept navigation callbacks as props.
- The user dropdown can be presentational if shared header behavior is not implemented elsewhere.
- The support email should be selectable and visually distinct.

## Suggested component structure

Use the codebase's existing conventions. If no equivalent components exist, a reasonable split is:

- `HelpAboutScreen.tsx`
- `HelpTopicCard.tsx` (optional)
- `HelpTopicDetail.tsx` or a modal component (optional)

Keep topic data in a typed array and avoid duplicating card markup.

## Acceptance criteria

- The screen closely matches the supplied screenshot at a desktop width of 1536 px.
- Sidebar, header, page heading, search card, five topic cards, and footer card are all present.
- Active navigation item is `Help & About`.
- Search filters the cards correctly and shows an empty state when appropriate.
- Each topic opens a readable answer/detail view.
- Layout scrolls vertically when needed and adapts gracefully to narrower screens.
- Implementation uses React Native + TypeScript + Expo and follows existing project conventions.
- Do not implement actual malware scanning, link reputation lookup, file upload, or backend API behavior in this screen.
